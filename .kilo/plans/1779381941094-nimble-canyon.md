# Plano: Corrigir upload de imagens ao Supabase Storage

## Problema

Ao importar uma clínica via Google Places, a imagem fica sem foto (`foto_url = None`). O fluxo atual é:
1. Busca detalhes no Google Places → obtém `photo_reference`
2. Constrói URL do Google Places Photo API
3. Tenta baixar e fazer upload para o Supabase Storage
4. Se falha → silenciosamente retorna `None` e a clínica fica sem imagem

## Causas raiz identificadas

1. **Erro engolido silenciosamente** (`image_storage.py:50-51`) — O `except Exception` captura qualquer erro, faz `print()` e retorna `None`. Impossível debugar.

2. **Bucket pode não existir** — O bucket `clinica-photos` precisa ser criado manualmente. Se não existe, o upload falha silenciosamente.

3. **Falta `load_dotenv()`** — `image_storage.py` lê env vars no topo mas não chama `load_dotenv()`.

4. **Sintaxe da API supabase-py v2.29.0** — Precisa confirmar se `upload(path, bytes, {"content-type": ...})` está correto.

## Mudanças

### 1. `backend-api/app/services/image_storage.py` — Reescrever

- Adicionar `load_dotenv()` e `logging` (seguir padrão de `google_places.py`)
- Mover leitura de env vars para dentro de `_get_supabase_client()` (lazy init)
- Usar `logger.error()` com traceback em vez de `print()`
- Adicionar `ensure_bucket_exists()` — criar o bucket automaticamente via API se não existir
- Levantar exceção se o upload falhar (não retornar `None` silenciosamente)

### 2. `backend-api/app/routers/clinicas.py` (endpoint de importação)

- Try/except em torno de `download_and_upload_image`
- Se falhar: logar o erro e criar a clínica sem foto (não bloquear a importação)
- O admin pode reimportar ou editar manualmente depois

## Arquivos a modificar

| Arquivo | Ação |
|---|---|
| `backend-api/app/services/image_storage.py` | Reescrever com logging, lazy init, auto-create bucket, error propagation |
| `backend-api/app/routers/clinicas.py` | Try/except com log + fallback graceful na importação |
